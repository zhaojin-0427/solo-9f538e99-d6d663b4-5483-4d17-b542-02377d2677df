# 广播剧混音审听台

声音导演交片前的逐段审听工具：上传同一集的两条轨（两台录音机，开头对得上、
越往后越偏），按两次打板在两轨上的采样号把 B 轨线性对到 A 轨，再按采样编号
设置/清除静音，两轨相加限幅到 16 位后按 5 秒一段逐段试听、确认，全部通过后
方可下载整集 WAV。

## 快速开始

### Docker Compose（推荐）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

### 本地运行

```bash
pip install -r app/requirements.txt
python3 app/app.py          # 监听 0.0.0.0:8000，可用 PORT 环境变量修改
```

打开页面后点 **载入内置样例** 即可立即试听（27 秒、44.1 kHz、6 段；B 机带
时钟漂移且开机更晚，长度与 A 不同）。样例打板采样号（直接填入对轨面板）：

| 打板 | A 轨采样号 | B 轨采样号 |
| --- | --- | --- |
| 第一次（0.5 s） | 22050 | 20616 |
| 第二次（24.5 s） | 1080450 | 1082191 |

对轨后可在段 0 听到头部补零、两个打板脉冲精确重合；第 3 段 10–11 秒处两轨
同相叠加，仍可听到限幅效果。样例由 `samples/make_samples.py` 生成。

## 使用流程

1. **上传**同一集的两条轨（轨 A / 轨 B）：16 位单声道 PCM WAV、同采样率；
   **两轨长度可以不同**——成片始终沿用 A 轨的时间轴与长度。上传即换新集，
   旧的对轨、静音、通过记录全部清空。
2. **打板对轨**：填入导演标记的两次打板采样号 `(a1,b1)`、`(a2,b2)`，两轨
   编号各自严格递增。服务端按
   `b(x) = b1 + (x − a1) · (b2 − b1) / (a2 − a1)` 把 A（成片）坐标 x 线性
   换算到 B 取样位置：
   - 取样位置落在 B 首末样点之外（`< 0` 或 `> nB−1`）→ 补零；
   - 轨内相邻样点线性插值，结果四舍五入（half away from zero，负半数也进位）；
   - B 轨静音始终按 **B 原轨采样号**，在插值之前置零；
   - 也可 **清除对轨** 回到恒等映射 `b(x)=x`。
3. **静音编辑**：按采样编号维护半开区间 `[起, 止)`。A 轨区间按成片（A 轨）
   坐标校验，B 轨区间按 B 原轨坐标校验（两轨长度不同时上界各自独立）。
4. **逐段审听**：混音每 5 秒一段（末段可不足 5 秒）。每段先 **▶ 试听**
   再 **✔ 确认通过**；确认时服务端校验"刚试听的混音"与该段当前内容一致
   （SHA-256 哈希），不一致则拒绝并要求重新试听。**仅实际 PCM 曾获确认的
   段落算通过。**
5. **下载整集**：各段都通过后才可下载整集 WAV。

## 交错保存与换集

- 对轨和静音的每次保存都带单调递增的 **版本号（乐观锁）**。提交时若另一项
  设置已被他处修改：
  - 请求带的版本过期 → 直接 `409 conflict`；
  - 锁外按段重算期间他处改动 → 提交前复查发现版本变化，同样 `409 conflict`。
  响应回传当前生效状态，前端提示"按当前设置重试"，一键用新版本重发；
  **任何冲突失败都不改变当时生效的混音与通过状态。**
- 每次上传生成新的 **集 ID**。换集后旧集的对轨/静音提交（含重算期间才换集
  的情形）一律 `409` 拒绝。
- 对轨/静音的重型哈希重算在 **全局锁之外按段进行**，重算期间其他窗口仍可
  试听、确认、保存；长录音下不会出现"一算就卡住全站"。

## 关键设计

- **通过状态由内容哈希驱动**：每段保存"曾被确认通过的混音哈希集合"，
  当前混音哈希 ∈ 集合即视为已通过。对轨或静音改动后，只有混音样本值实际
  变化的段需要重听；内容改回某个已确认版本（包括把对轨切回去）自动恢复通过。
- **试听与新下载用生效对轨**：分段试听、确认、下载全部基于当前生效的对齐
  参数与静音表；未确认过的新 PCM 不会被算作通过。
- **下载快照**：开始下载时（须全部通过）即快照轨道引用、静音表 **与对轨
  参数**，之后流式生成。下载进行中他处改对轨/静音/重传，**本次下载继续
  交付当时通过的混音**；改动失效后的新下载被门控，重新逐段通过后才开放。
- **单段缓冲**：对轨计算与下载都按段生成、逐段发送，应用层内存中最多另存
  **一段**对齐后的 B 轨 PCM（源轨 PCM 整体常驻内存，这是混音的数据来源，
  非"对齐缓冲"）。
- **停读不阻塞**：流式生成器不持有全局锁；多线程 WSGI（waitress）下，
  浏览器停读或断连只占用该下载自身线程。
- **跨窗口共享**：状态保存在服务端单例中，前端每 2 秒轮询同步他处改动；
  本地正在编辑对轨/静音面板时给出冲突提示而不覆盖输入。

## API 一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 审听页面 |
| POST | `/api/upload` | 上传 `track_a` / `track_b` 两个 WAV（multipart），同采样率即可、长度可不同 |
| POST | `/api/load_sample` | 载入内置样例 |
| GET | `/api/state` | 剧集信息（含集 ID、两轨长度、对轨参数与斜率、版本号）、各段状态、静音表 |
| POST | `/api/alignment` | 保存对轨 `{"a1","b1","a2","b2","version"?}`，或 `{"clear":true}` 清除；冲突 409 |
| POST | `/api/mutes` | 保存静音 `{"A": [[s,e],...], "B": [...], "version"?}`（缺省轨保持原样）；冲突 409；返回失效段 |
| GET | `/api/segment/<i>.wav` | 第 i 段混音 WAV（按生效对轨），响应头 `X-Mix-Hash` 为该段混音哈希 |
| POST | `/api/confirm/<i>` | 确认通过，请求体 `{"hash": 试听时拿到的哈希}` |
| GET | `/api/download` | 全部通过后才可下载整集 WAV（流式，快照对轨+静音） |

## 交付报告

### 已做成

- 打板线性对轨：四点采样号校验（两轨各自严格递增、不越界）、线性换算、
  越界补零（头/尾）、轨内线性插值、四舍五入（含负半数远离零）、可清除回恒等
- 成片沿用 A 轨时间轴与长度；两轨允许不等长、同采样率；B 静音按 B 原轨
  采样号在插值前置零，A 静音按成片坐标
- 对轨/静音交错保存的版本号乐观锁：预检 + 提交前复查，冲突 409 回传新
  状态、前端一键重试；失败保留当时生效混音
- 换集（重传）生成新集 ID，旧集提交一律拒绝；重算锁外按段进行，不阻塞试听/保存
- 哈希驱动的精确失效与内容复原自动恢复通过；仅确认过的 PCM 算通过
- 全通过才可下载；下载快照对轨+静音，已开始的下载继续交付旧混音，逐段流式
  生成（单段对齐 B 缓冲）
- 内置漂移样例（不等长、头部补零、打板脉冲可对齐、限幅演示）；Docker Compose 启动
